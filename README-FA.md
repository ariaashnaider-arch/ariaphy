# Aria Wasmer

نسخهٔ Wasmer یک پنل فارسی و یک سرور **VLESS روی WebSocket** در همان اپ است. `main.py` با پایتون اجرا می‌شود. TLS عمومی را Wasmer در دامنهٔ HTTPS برقرار می‌کند. تمام وابستگی‌های برنامه در بسته هستند.

## دیپلوی روی همان اپ `ariaphy`

۱. ZIP را باز کن. `main.py`، `edge_config.py`، `edge_tunnel.py`، `requirements.txt` و پوشه‌های `static/` و `vendor/` باید در ریشهٔ مخزن `ariaphy` باشند. اگر از مخزن قبلی استفاده می‌کنی، `main.py` و `requirements.txt` جدید را جایگزین فایل‌های قبلی کن. پوشهٔ `runtime/` نسخهٔ قبلی برای این اپ استفاده نمی‌شود.

۲. برای ساخت رمز و کلید، فایل `setup-keys.html` را بعد از استخراج ZIP در مرورگر باز کن و «تولید رمز و کلید» را بزن. اگر مرورگر گوشی فایل محلی را اجرا نکرد، می‌توانی یک بار برنامه را بدون متغیرها Deploy کنی. صفحهٔ `https://ariaphy.wasmer.app/` حالت راه‌اندازی و دکمهٔ تولید کلید را نشان می‌دهد. تولید کلید در مرورگر انجام می‌شود.

۳. در فرم Wasmer این مقادیر را وارد کن.

| کادر | مقدار |
|---|---|
| Project link | `ariaphy` |
| Project preset | `Python` |
| Start Command | `python main.py` |
| Build Command | خاموش یا خالی |
| Install Command | خاموش یا خالی |
| Enable Database | خاموش |
| Environment variables | کلیدها و مقدارهای جدول بعد |

| Key | Value |
|---|---|
| `ARIA_ADMIN_PASSWORD` | رمز خصوصی تولیدشده. رمز دلخواه هم می‌تواند حداقل ۱۶ کاراکتر و حداکثر ۲۵۶ بایت باشد. |
| `ARIA_SIGNING_KEY` | کلید ۶۴ نویسه‌ای هگز که صفحهٔ تولید کلید می‌دهد |
| `ARIA_PUBLIC_HOST` | `ariaphy.wasmer.app`. برای همین نام اختیاری است. اگر دامنه را عوض کردی، مقدار جدید را بدون `https://` وارد کن. |

مقادیر خصوصی را در مخزن قرار نده. اگر `PORT` را قبلاً دستی اضافه کرده‌ای، آن ردیف را حذف کن. برنامه از `PORT` محیط استفاده می‌کند و پیش‌فرضش `80` است. [راهنمای اجرای Python در Wasmer](https://docs.wasmer.io/edge/guides/python/)

۴. بعد از Deploy، دامنهٔ `ariaphy.wasmer.app` را باز کن. با رمز مدیر وارد شو، یک کانفیگ بساز و «تست اتصال» را بزن. پیام `HTTP 200` یا هر کد HTTP از `example.com` نشان می‌دهد WebSocket، احراز VLESS و اتصال خروجی آزمایشی برقرار شده‌اند. بعد لینک یا QR را در کلاینت وارد کن. پورت عمومی `443`، نوع انتقال `WS`، TLS فعال و Flow و Mux خاموش باشد. برای کلاینت‌هایی که DNS را در تونل می‌فرستند، از DNS روی HTTPS استفاده کن.

## به‌روزرسانی برای خطای بسته‌شدن WebSocket

اگر نسخهٔ قبلی همین پنل Wasmer را اجرا کرده‌ای، از این ZIP فقط `edge_tunnel.py` و `static/app.js` را در مسیرهای متناظر جایگزین کن و دوباره Deploy بزن. سپس صفحه را تازه کن و «تست اتصال» را بزن. نتیجه مرحلهٔ WebSocket، DNS و اتصال TCP را جدا می‌کند. در صورت خطا، سطرهای `aria tunnel` در Logs اپ، مرحله و نوع خطا را نشان می‌دهند.

## دامنهٔ این نسخه

- کانفیگ‌های تازهٔ **VLESS + WS + TLS** برای TCP به مقصدهای عمومی IPv4 روی پورت‌های ۸۰ و ۴۴۳. اعتبار انتخابی ۱ تا ۹۰ روز است و زمان پایان دقیق در پنل نمایش داده می‌شود.
- اعتبار لینک‌ها در خود UUID امضا می‌شود. لینک‌های صادرشده را ذخیره کن. با همان `ARIA_SIGNING_KEY` و همان دامنه، بعد از استقرار دوباره هم تا تاریخ انقضا معتبرند. تغییر کلید امضا همهٔ لینک‌های قبلی را باطل می‌کند. با این روش، فهرست کاربران و لغو تکی روی سرور وجود ندارد.
- تنظیمات و کاربران نسخهٔ لینوکسی، فروشگاه، تلگرام، UDP، XHTTP و پروتکل‌های دیگر بخشی از این نسخهٔ Wasmer نیستند. هر تونل پس از حداکثر ۱۵ دقیقه بسته می‌شود و کلاینت می‌تواند اتصال تازه بسازد.
- `/health` وضعیت اجرای اپ و تکمیل متغیرها را نشان می‌دهد. آزمون داخل پنل مسیر WebSocket و شبکهٔ خروجی را جداگانه می‌سنجد. [WebSocket در Wasmer Edge](https://github.com/wasmerio/edge-multiplayer-games)

ورود، تولید لینک، رد کردن مقصد خصوصی و عبور رفت‌وبرگشت TCP از WebSocket در اجرای محلی آزموده شده‌اند. نتیجهٔ آزمون روی خود Wasmer بعد از Deploy در پنل دیده می‌شود.

## مجوزها

پیاده‌سازی VLESS بر اساس ساختار پیام رسمی Xray است. بسته شامل `wsproto 1.3.2` و `h11 0.16.0` است. فایل‌های فونت و QR از رابط Aria بازیابی شده‌اند. مجوز اجزای استفاده‌شده در `licenses/` قرار دارد. [مستندات پروتکل VLESS](https://xtls.github.io/en/development/protocols/vless.html)
