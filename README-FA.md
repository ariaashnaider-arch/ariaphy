# اجرای پنل Aria 4.11.1 با Python

فایل ZIP را باز کن و محتویات آن را در ریشهٔ پروژه قرار بده. `main.py` و پوشهٔ `runtime` باید کنار هم باشند. راه‌انداز با Python اجرا می‌شود و باینری آمادهٔ پنل را اجرا می‌کند. رابط پنل، تنظیمات و API همان پروژهٔ Aria هستند.

## تنظیم صفحهٔ دیپلوی

| گزینه | مقدار |
|---|---|
| نوع سرویس | Web Service / Python |
| نسخهٔ Python | 3.10 یا جدیدتر |
| Install Command | خالی یا پیش‌فرض هاست |
| Build Command | `python main.py --prepare` |
| Start Command | `python main.py` |
| پورت داخلی | مقدار `PORT` که هاست می‌دهد. پیش‌فرض برنامه `8080` است. |
| مسیر بررسی سلامت، در صورت وجود کادر | `/health` |

اگر فقط کادر Start Command داری، `python main.py` آماده‌سازی را هم انجام می‌دهد. اگر فرمان پیش‌فرض هاست `python3` است، همان را در هر دو کادر بنویس. در نصب تازه، متغیر `ARIA_ADMIN_PASSWORD` را در Secrets با رمز خصوصیِ حداقل ۱۲ نویسه وارد کن. `ARIA_ADMIN_USER` اختیاری است و مقدار پیش‌فرضش `admin` است.

این بسته به محیط **Linux x86_64**، اجازهٔ اجرای باینری و فرایند فرزند، و یک مسیر قابل نوشتن برای آماده‌سازی نیاز دارد. محل پیش‌فرض آماده‌سازی `.aria-runtime/` است. اگر مسیر دیگری برای اجرای فایل‌های باینری روی هاست داری، آن را در `ARIA_RUNTIME_DIR` مشخص کن. برای هاست با ریشهٔ فقط‌خواندنی، مرحلهٔ Build باید پوشهٔ آماده‌شده را به محیط اجرا منتقل کند.

## آماده‌سازی هسته

در اجرای اول، راه‌انداز هستهٔ رسمی **3x-ui 3.8.5 / Xray** را از GitHub دریافت و SHA-256 آن را بررسی می‌کند. اگر هاست به GitHub دسترسی خروجی ندارد، آرشیو `x-ui-linux-amd64.tar.gz` را از انتشار رسمی بگیر و در پوشهٔ `runtime/` بگذار. مسیر یک فایل محلی روی هاست را می‌توان در `ARIA_ENGINE_ARCHIVE` هم مشخص کرد. [آرشیو رسمی 3x-ui](https://github.com/MHSanaei/3x-ui/releases/download/v3.8.5/x-ui-linux-amd64.tar.gz)

در محیط وب، برای کانفیگ‌های WS، عبور WebSocket از پروکسی دامنه باید فعال باشد. پس از Deploy، دامنهٔ HTTPS پنل را باز کن. پاسخ `200` از `/health` آمادگی پنل و API هسته را نشان می‌دهد. برای سنجش اتصال VPN، یک کانفیگ WS را در کلاینت امتحان کن.

اگر هاست دیسک دائمی دارد، مسیر همان دیسک را در `ARIA_DATA_DIR` بگذار و Replica را روی ۱ نگه دار. برای ارتقا، از همان مسیر دادهٔ نصب قبلی استفاده کن. روی دیسک موقت، تنظیمات و حساب‌های ذخیره‌شده ممکن است پس از بازسازی سرویس از بین بروند.

`sing-box` وصله‌شدهٔ پروژه و Ookla Speedtest اجزای اختیاریِ جدا هستند. برای فعال کردنشان می‌توان مسیر باینری‌های اجرایی را در `ARIA_SING_BOX_BIN` و `ARIA_SPEEDTEST_BIN` گذاشت. راه‌اندازی معمول پنل و کانفیگ‌های Xray به این دو فایل وابسته نیست.
